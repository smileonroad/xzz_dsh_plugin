# web：浏览器 GUI

> 相关代码：`apps/cli`（dsh web）、[demo/run-web.mjs](../../demo/run-web.mjs)、[demo/web-cordis.local.yml](../../demo/web-cordis.local.yml)

前面三个 surface 全是命令行，冷冰冰的。web 是**唯一带图形界面**的——本地起一个 webserver，浏览器打开即用：聊天 UI、工具树、settings、权限面板、workflow 视图，全在 GUI 里。它也是四个 surface 里唯一「人在回环」的：危险操作弹框问你，你点头它才动。

## 是什么

web 是 DSH 四个 surface 里唯一带图形界面的：本地 webserver + API 网关，浏览器打开即用。架构上它是**双层**：

- **host（Node）**：负责 API 网关和权限执行。
- **browser**：负责 UI 展示。

中间走 api-gateway 代理。权限在浏览器里人工确认——web 是「人在回环」的 surface，不是无人值守。

## 怎么用（运行 demo）

[demo/run-web.mjs](../../demo/run-web.mjs) 是 web 运行器：

```bash
node demo/run-web.mjs                    # web demo（自指 Cordis 工具），端口 3081
node demo/run-web.mjs --patch <file>     # 追加其他 overlay（可多次）
node demo/run-web.mjs --no-cordis        # 普通 web，不加自指 overlay
```

## demo 代码说明

`run-web.mjs` 干的事和 headless 运行器很像，只是入口从 `--profile headless` 换成了 `web` 子命令，并且**默认追加一个本地 overlay**（[demo/web-cordis.local.yml](../../demo/web-cordis.local.yml)，pin 端口 3081）：

```js
const child = spawn(process.execPath, ['--import', 'tsx/esm', DSH_BIN, 'web',
  ...(skipCordis ? [] : ['--patch', CORDIS_OVERLAY]),
  ...patches.flatMap(p => ['--patch', p]),
  '--no-open'], {
  cwd: process.cwd(),
  env: { ...process.env, DEEPSEEK_BASE_URL: '...' },
  stdio: 'inherit',
})
```

关键点：

- `web` 子命令：启动 webserver + api-gateway（默认端口 3080）。
- 本地 overlay 把端口 pin 到 **3081**，启动后脚本自己打印 URL（`--no-open` 关闭自动开浏览器——无头/重定向环境下自动开浏览器会把 boot 卡住）。
- 自指 Cordis 工具（agent 查看当前 Cordis 进程、在内存中挂载/卸载模型写的插件）**已由 dsh-web-app bundle 内置**，UI 里开箱即用，不需要额外 overlay。
- **参数顺序是硬规则**：launcher 自己的 flags（`--patch`、`--dump-config`）必须在 app 自己的 flags（`--no-open` 等）**之前**——launcher 的 `passThroughOptions` 会把第一个未知选项之后的全部参数透传给 app，顺序错了 `--patch` 会被 app 当成未知选项拒绝。
- **loader 必须是 `tsx/esm`**：headless/acp 用 `tsx` 能跑，web 模式用 `tsx` 会静默卡死（rc.2 实测），换 `tsx/esm` 才正常。

## 自定义模型配置

web 连本地网关时，url 和 key 的机制与 headless 一致：

1. **url（网关地址）**：`DEEPSEEK_BASE_URL` 由启动环境提供（bootstrap-only，不能放 `.env`），[demo/run-web.mjs](../../demo/run-web.mjs) 从环境变量读取后透传给子进程。换网关改环境变量即可。
2. **key**：根 `.env` 提供 `DEEPSEEK_API_KEY`，由 bin 的 `loadEnv` 加载。
3. **模型名称**：和 headless 一样，web 的默认模型来自 base bundle 的 `agent-default-model`，`run-web.mjs` 支持 `--patch` 透传，用同一个 [demo/model.patch.yml](../../demo/model.patch.yml) 覆盖即可：

   ```bash
   node demo/run-web.mjs --patch demo/model.patch.yml
   ```

## 怎么跑通

1. `dsh web` 启动 webserver（默认 3080），打印绑定 URL。
2. `DEEPSEEK_BASE_URL` 同样是 bootstrap-only，运行器脚本在 env 里显式传入。
3. **不需要 `DSH_PERMISSION_MODE`**——权限走浏览器里的人工确认。
4. 长驻进程，Ctrl+C 退出。脚本打印 URL，浏览器手动打开。

## 执行结果输出

实跑（网关由 `DEEPSEEK_BASE_URL` 启动环境提供；只启动不对话时不调用模型，占位地址也能跑）：

```bash
node demo/run-web.mjs
```

终端只打印两行启动信息，之后的全部交互都在浏览器里：

```
[demo/run-web.mjs] 浏览器打开 http://127.0.0.1:3081 （Ctrl+C 退出）
dsh web: http://127.0.0.1:3081
```

- 端口 3081 由本地 overlay pin 住（不挂 overlay 的普通 web 默认 3080）。
- 终端没有模型输出——对话、权限确认、工具结果全在浏览器 UI 里，会话落盘到 session 日志。
- 长驻进程，Ctrl+C 退出。

## 踩过的坑

**端口被占用（EADDRINUSE 3081）。** 首次启动报端口冲突——3081 已被先前手动运行的一个 web 实例占住（PID 12704，node.exe）。解决：确认该进程是残留的 web 实例后，`taskkill //F //PID 12704` 杀掉，端口释放后重启成功。

> 注意：杀进程前先确认它确实是你要停的那个 web 服务，不要误杀无关进程。

**上游 overlay 与 bundle 重复 insert。** `examples/web-cordis/cordis.yml` 会 insert `cordis-host-runner` 和 `tool-cordis`，但当前 `dsh-web-app` bundle 已经内置这两行——再 insert 一次直接报 `duplicate loader entry id: cordis-host-runner`，boot 失败。解决：demo 用本地精简 overlay（[demo/web-cordis.local.yml](../../demo/web-cordis.local.yml)）只 pin 端口，自指工具由 bundle 原生提供。上游示例与 bundle 版本漂移时，先 dump-config 看 bundle 里已有什么再决定 overlay 内容。

**参数顺序：launcher flags 必须在 app flags 之前。** `dsh web --no-open --patch x` 会报 `unknown option '--patch'`——launcher 的 `passThroughOptions` 把第一个未知选项（`--no-open`）之后的参数全部透传给 app，launcher 就不再消费 `--patch`。正确顺序是 `dsh web --patch x --no-open`。

**web 模式的 tsx loader 必须 `tsx/esm`。** headless/acp 的子进程用 `--import tsx` 能跑，web 模式用 `tsx` 会静默卡死（无输出、端口不监听），换 `tsx/esm` 立即正常。四个 surface 的运行器不必共用同一个 loader 写法，以实测为准。

## 验证方式

- 启动成功：进程打印绑定 URL，浏览器打开能出现 UI。
- 会话持久：浏览器里开的会话写入 session log（schedule 篇会用到）。
- 权限面板：危险操作时浏览器弹出确认，人工点同意后工具才执行。

## 使用场景

- **人机对话**：需要图形界面和人工审批的交互式使用。
- 配置/调试可视化：settings、工具树、workflow 视图都在浏览器里看。
- web-cordis 自指示例：agent 能查看当前 Cordis 进程、在内存中挂载/卸载模型写的插件（等于 agent 修改自己的运行时，**安全上按 shell 权限对待**）。

## 特点

- **唯一 GUI**：webserver + api-gateway + host/browser 双层架构。
- **人工在回环**：权限浏览器确认，无需 `DSH_PERMISSION_MODE`。
- **组合驱动**：`agent-presets` 做 per-session 组合，`--patch` 叠加 overlay。
- **长驻会话**：不同于 headless 的一次性，浏览器会话持续存在。
