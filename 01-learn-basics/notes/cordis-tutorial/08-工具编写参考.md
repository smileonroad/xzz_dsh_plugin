## 8.1 最小形态：唯一的新东西是转发 signal

cookbook 的最小形态（`read_file` 工具）和第 7 章的 greet 几乎同构，唯一的新增模式是这一行：

```ts
return readFile(args.path, { encoding: 'utf8', signal: exec.signal })
```

**把 `exec.signal` 转发给 node 的 I/O API** —— 这就是「遵守 `exec.signal`」的具体做法。对照 [7.6](07-进入-harness.md#76-signal必填的取消句柄) 的实测：不转发 signal 的 body 不会被杀，只能等它自然跑完、由流水线在结果层替换成 `ABORTED`；转发了才能让 node 内部**真正提前中断 I/O**。

文档另外两句都是旧知识：「注册基于副作用：dispose 插件 fiber 即注销该工具」= [7.5](07-进入-harness.md#75-register-返回-disposer注销与-toolschange)；「schema 会自动流入系统提示词的组装过程」= [7.1](07-进入-harness.md#71-注册一个模型可调用的工具) 的 `wireSchemas`（`packages/core/tools/src/index.ts:825`）。

「注册借用你的只读定义：注册后不要修改其 schema 或替换回调」是一条**约定**而非强制机制 —— 注册表直接持有你给的对象引用（`layer.tools.insert(name, definition)`，`index.ts:1049`），改了它注册表就真的会看到。🚧 「改了会怎样」我没有实测，也不建议试。

## 8.2 执行策略与观测：五个扩展点全景

> ⭐ 本章主菜。本节把第 7 章 §7.2 留下的 🚧（「waterfall 拦截这条路我没有实测」）补上了。

文档的核心主张：**尽量不要把部署策略内建到工具中**。允许/拒绝/询问是策略，截止时间/重试/指标是运维，脱敏/改写是合规 —— 它们都该挂在钩子上，工具本体只管业务。五个扩展点按执行顺序：

| 序 | 扩展点 | 模式 | 能干什么 |
|---|---|---|---|
| 1 | `tools/pre-execute` | waterfall | 决定**跑不跑**：`allow` / `deny(reason)` / `ask` |
| 2 | `ctx.tools.guard()` | 同步函数 | **单调最终拒绝**：返回字符串即拒绝，谁也翻不了案 |
| 3 | `tools/execute` | waterfall | **环绕分发**：截止时间、重试、指标；可替换 `exec.signal` |
| 4 | `tools/post-execute` | waterfall | **改写结果**：accept（换 content 或 value）/ block / 附加上下文 |
| 5 | `tools/result` | emit | **纯观察**：什么都改不了（[7.2](07-进入-harness.md#72-为什么-logger-先于-execute-返回打印)） |

### 🧪 实验：一次成功调用穿过全部五层

每个钩子里打一行编号日志，看真实顺序：

**📄 文件** `01-learn-basics/examples/cordis-tutorial/08-policy-chain/policy-chain.ts`

```ts
import type { Context } from '@deepseek-ai/cordis'
import { brandString } from '@deepseek-ai/dsh-brand'
import { defineTool } from '@deepseek-ai/dsh-tools'
import type { ToolCallId } from '@deepseek-ai/dsh-llm'

export const name = 'policy-chain'
export const inject = ['tools']

export function apply(ctx: Context) {
  // ① pre-execute：可扩展的 允许/拒绝/询问 策略门
  ctx.on('tools/pre-execute', async (exec, next) => {
    console.log('1. [pre-execute] 看到调用:', exec.name)
    const decision = await next()   // 委托内层；最内层默认 { kind: 'allow' }
    console.log('2. [pre-execute] 决策:', decision.kind)
    return decision
  })

  // ② guard：单调的最终拒绝（在 pre-execute 之后检查）
  ctx.tools.guard(exec => {
    console.log('3. [guard] 检查:', exec.name)
    return undefined                 // undefined = 放行；返回字符串 = 拒绝理由
  })

  // ③ tools/execute：环绕分发的包装器（截止时间/重试/指标的位置）
  ctx.on('tools/execute', async (exec, next) => {
    console.log('4. [execute 包装] 分发前')
    const result = await next()
    console.log('6. [execute 包装] 分发后, isError =', result.isError)
    return result
  })

  // ④ post-execute：规范化结果的接受/替换/阻止
  ctx.on('tools/post-execute', async (exec, result, next) => {
    console.log('7. [post-execute] 看到结果, isError =', result.isError)
    return next()                    // accept
  })

  // ⑤ tools/result：纯观察，改不了任何东西
  ctx.on('tools/result', (exec, result) => {
    console.log('8. [tools/result] 最终结果:', JSON.stringify(result.content))
  })

  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet the named person.',
    parameters: {
      name: { type: 'string', required: true, description: 'Who to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      console.log('5. [body] execute 运行')
      return `Hello, ${args.name}!`
    },
  }))

  void (async () => {
    const r = await ctx.tools.execute({
      callId: brandString<ToolCallId>('chain-1'),
      name: 'greet',
      arguments: { name: 'Cordis' },
      signal: new AbortController().signal,
    })
    console.log('9. [调用方] 收到:', JSON.stringify(r.content))
  })()
}
```

- `pre-execute` waterfall：`prepareExecution`（`index.ts:1465-1468`），最内层默认 `{ kind: 'allow' }`；
- `guard` 在 waterfall **之后**：`index.ts:1476-1478` —— 只有决策是 `allow` 时才查 `guardReason`（已被 deny 的调用不需要再 guard）；
- `tools/execute` 环绕 body：waterfall 签名见 `index.ts:155`，包装 `dispatchToolBody`；
- `post-execute` waterfall：`postExecute`（`index.ts:1732-1736`），默认 `accept`；
- `tools/result`：`notifyResult`（`index.ts:1655-1657`），在返回调用方之前 —— 7.2 已证。

`ctx.tools.guard` 的签名极简（`ToolGuard`，`index.ts:704`）：`(execution) => string | undefined` —— 同步、返回拒绝理由或 undefined。它也是 effect（`index.ts:1100-1106`，走同一个 `layers.effect`），插件卸载自动撤销。

### 🧪 实验：两层拒绝 —— pre-execute deny 与 guard 单调拒绝

**📄 文件** `01-learn-basics/examples/cordis-tutorial/08-deny-guard/deny-guard.ts`

```ts
import type { Context } from '@deepseek-ai/cordis'
import { brandString } from '@deepseek-ai/dsh-brand'
import { defineTool } from '@deepseek-ai/dsh-tools'
import type { ToolCallId } from '@deepseek-ai/dsh-llm'

export const name = 'deny-guard'
export const inject = ['tools']

const tool = (name: string) => defineTool({
  name,
  description: `The ${name} tool.`,
  parameters: {},
  output: {
    schema: { type: 'string' },
    render: (_args, value) => [{ type: 'text', text: value }],
  },
  async execute() {
    console.log(`   [${name} body] 如果打印了说明没被拒`)
    return `${name} ok`
  },
})

export function apply(ctx: Context) {
  // 第一层：pre-execute 拒绝 greet，放行 secret（委托给内层默认 allow）
  ctx.on('tools/pre-execute', async (exec, next) => {
    if (exec.name === 'greet') {
      return { kind: 'deny', reason: 'greet 不在允许清单里' }
    }
    return next()
  })

  // 第二层：guard —— 即使 pre-execute 放行，guard 仍能单调拒绝
  ctx.tools.guard(exec =>
    exec.name === 'secret' ? 'guard: secret 被永久禁止' : undefined,
  )

  ctx.tools.register(tool('greet'))
  ctx.tools.register(tool('secret'))

  void (async () => {
    const signal = new AbortController().signal

    const r1 = await ctx.tools.execute({
      callId: brandString<ToolCallId>('d1'),
      name: 'greet',
      arguments: {},
      signal,
    })
    console.log('① pre-execute 拒绝 → isError:', r1.isError)
    console.log('① content:', JSON.stringify(r1.content))

    const r2 = await ctx.tools.execute({
      callId: brandString<ToolCallId>('d2'),
      name: 'secret',
      arguments: {},
      signal,
    })
    console.log('② guard 拒绝 → isError:', r2.isError)
    console.log('② content:', JSON.stringify(r2.content))
  })()
}
```

**观察**：

1. 两个 body 探针都**没打印** —— 拒绝发生在分发之前（`index.ts:1479-1489`：deny 直接物化成 `Error: <reason>` 的错误结果）；
2. `secret` 走完了 pre-execute（allow）仍被 guard 拦下 —— 「单调」的意思：guard 只能拒绝，**任何后续监听器都无法 force-allow 别的 guard 拒掉的调用**（`index.ts:1093-1095` 注释原文）；
3. 拒绝理由原样进入模型可见的 content —— 模型能读到「为什么被拒」，这是它自我纠正的输入。

`ask` 分支（转人工审批）🚧 未实测：需要 `approval` 服务在场；缺席时 `ask` 退化为拒绝（`serviceAsk`，`index.ts:1679+`，源码可见）。

### 🧪 实验：post-execute 改写与阻止

**📄 文件** `01-learn-basics/examples/cordis-tutorial/08-post-execute/post-execute.ts`

```ts
import type { Context } from '@deepseek-ai/cordis'
import { brandString } from '@deepseek-ai/dsh-brand'
import { defineTool } from '@deepseek-ai/dsh-tools'
import type { ToolCallId } from '@deepseek-ai/dsh-llm'

export const name = 'post-execute-demo'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.on('tools/post-execute', async (exec, result, next) => {
    // r1：接受，但替换模型可见的 content
    if (exec.callId === 'r1') {
      return { kind: 'accept', content: [{ type: 'text', text: '[内容已被 post-execute 替换]' }] }
    }
    // b1：阻止 —— 把纠正性反馈变成错误结果
    if (exec.callId === 'b1') {
      return { kind: 'block', feedback: [{ type: 'text', text: '[结果被阻止：请先确认目标]' }] }
    }
    // 其余：放行
    return next()
  })

  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet the named person.',
    parameters: {
      name: { type: 'string', required: true, description: 'Who to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))

  void (async () => {
    const signal = new AbortController().signal
    const call = (id: string, who: string) => ctx.tools.execute({
      callId: brandString<ToolCallId>(id),
      name: 'greet',
      arguments: { name: who },
      signal,
    })

    const r1 = await call('r1', 'Replace')
    console.log('① 替换 content → isError:', r1.isError)
    console.log('① content:', JSON.stringify(r1.content))
    console.log('① value（程序化访问不受影响）:', JSON.stringify('value' in r1 ? r1.value : undefined))

    const r2 = await call('b1', 'Block')
    console.log('② block → isError:', r2.isError)
    console.log('② content:', JSON.stringify(r2.content))

    const r3 = await call('n1', 'Normal')
    console.log('③ 放行 → content:', JSON.stringify(r3.content))
  })()
}
```

**三个观察**：

1. **替换 content 不动 value**：模型看到替换后的文本（脱敏场景），但 `result.value` 仍是原始规范值 `"Hello, Replace!"`。`value` 是「执行本地的规范值，deliberately omitted from durable events」（`index.ts:549-552`）—— 持久化的是 content 和 meta，不是 value；
2. **block 把成功翻成失败**：`isError: true`，feedback 成为 content（`index.ts:1738-1746`）—— 用于「结果不可接受，给模型一段纠正性反馈」；
3. `PostToolDecision` 的完整形状（`index.ts:590-594`）：`accept` 可带 `content`（换渲染）**或** `value`（换规范值，会重新过 output.schema 校验 + 重新 render，`index.ts:1758-1770`），二者互斥；失败的 result 不允许换 value；还可以带 `additionalContexts` 给下一次模型请求附加上下文。🚧 换 value / 互斥报错 / additionalContexts 三个分支未实测。

## 8.3 规范值契约的另一半：output.schema 也会被校验

文档规则：「`execute` 只返回推导出的值；注册表将其快照为无损 JSON，**完成校验和冻结后**，再交给 `output.render`」「抛出异常或返回无效值意味着 `isError`」。第 7 章只测了**输入**校验，这里测**输出**侧：

**📄 文件** `01-learn-basics/examples/cordis-tutorial/08-output-invalid/output-invalid.ts`

```ts
import type { Context } from '@deepseek-ai/cordis'
import { brandString } from '@deepseek-ai/dsh-brand'
import { defineTool } from '@deepseek-ai/dsh-tools'
import type { ToolCallId } from '@deepseek-ai/dsh-llm'

export const name = 'output-invalid'
export const inject = ['tools']

export function apply(ctx: Context) {
  // ① execute 返回违反 output.schema 的值：声明 string，返回数字
  ctx.tools.register(defineTool({
    name: 'bad-output',
    description: 'Returns a number despite declaring a string output.',
    parameters: {},
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute() {
      // @ts-expect-error 故意的：演示注册表对返回值的校验
      return 42
    },
  }))

  // ② execute 直接抛异常（基础设施故障的正确表达方式）
  ctx.tools.register(defineTool({
    name: 'throws',
    description: 'Always throws.',
    parameters: {},
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute() {
      throw new Error('disk on fire')
    },
  }))

  void (async () => {
    const signal = new AbortController().signal

    const r1 = await ctx.tools.execute({
      callId: brandString<ToolCallId>('o1'),
      name: 'bad-output',
      arguments: {},
      signal,
    })
    console.log('① 违反 output.schema → isError:', r1.isError, '| code:', r1.error?.info?.code)
    console.log('① content:', JSON.stringify(r1.content))

    const r2 = await ctx.tools.execute({
      callId: brandString<ToolCallId>('o2'),
      name: 'throws',
      arguments: {},
      signal,
    })
    console.log('② body 抛异常 → isError:', r2.isError)
    console.log('② content:', JSON.stringify(r2.content))
  })()
}
```

**观察**：

1. **类型系统骗不过运行时** —— `@ts-expect-error` 只能骗过编译器；注册表对成功值做 快照 → 按 `output.schema` 校验 → `deepFreeze` → 交给 `render`（`createSuccessResult`，`index.ts:1783-1795`），违规抛 `ToolOutputError`（code `INVALID_TOOL_OUTPUT`，`index.ts:506-515`），最终成为 `isError` 结果；
2. **body 抛的异常不会炸进程** —— 被 catch 转成 `Error: disk on fire` 的错误结果（`index.ts:1608-1610`）。文档的指导：**基础设施故障抛异常；领域性的「不理想状态」（如进程非零退出码）写进规范值**，让 render 去解释 —— 前者是「工具坏了」，后者是「工具好好地告诉你是个坏消息」。🚧 这个设计区分的对照示例未实测。

## 8.4 Schema DSL：深度与边界

文档说校验覆盖「类型、必填键、字面量约束、**恰好匹配一个分支的联合**以及嵌套值」，同时明说 DSL 有表达不了的约束。一个实验测完深度和边界：

**📄 文件** `01-learn-basics/examples/cordis-tutorial/08-nested-schema/nested-schema.ts`

```ts
import type { Context } from '@deepseek-ai/cordis'
import { brandString } from '@deepseek-ai/dsh-brand'
import { defineTool } from '@deepseek-ai/dsh-tools'
import type { ToolCallId } from '@deepseek-ai/dsh-llm'

export const name = 'nested-schema'
export const inject = ['tools']

export function apply(ctx: Context) {
  const tool = defineTool({
    name: 'query',
    description: 'Query with a nested filter.',
    parameters: {
      name: { type: 'string', required: true, description: 'Who' },
      filter: {
        type: 'object',
        additionalProperties: false,          // 显式对象节点【必须】声明开放性
        description: 'Nested filter',
        properties: {
          tags: { type: 'array', items: { type: 'string' }, description: 'Tag list' },
          mode: {
            // 恰好一个分支：两个 const 互斥
            oneOf: [{ type: 'string', const: 'fast' }, { type: 'string', const: 'slow' }],
            description: 'Exactly one',
          },
          style: {
            // 故意重叠：'a' 会同时命中两个分支 → 违反「恰好一个」
            oneOf: [{ type: 'string' }, { type: 'string', enum: ['a', 'b'] }],
          },
        },
      },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      console.log('   [body] 收到 args:', JSON.stringify(args))
      return 'ok'
    },
  })

  ctx.tools.register(tool)

  console.log('生成的 JSON Schema（紧凑）:')
  console.log(JSON.stringify(tool.parameters))
  console.log('')

  void (async () => {
    const signal = new AbortController().signal
    const call = (id: string, args: unknown) => ctx.tools.execute({
      callId: brandString<ToolCallId>(id),
      name: 'query',
      arguments: args,
      signal,
    })

    const a = await call('n-a', { name: 'ada', filter: { tags: ['x'], mode: 'fast' } })
    console.log('A 合法嵌套 →', JSON.stringify(a.content), '\n')

    const b = await call('n-b', { name: '', filter: { mode: 'slow' } })
    console.log('B 空字符串 → isError:', b.isError, '（schema 放行了！）\n')

    const c = await call('n-c', { name: 'x', filter: { mode: 'other' } })
    console.log('C oneOf 零命中 →', JSON.stringify(c.content), '\n')

    const d = await call('n-d', { name: 'x', filter: { style: 'a' } })
    console.log('D oneOf 双命中 →', JSON.stringify(d.content), '\n')

    const e = await call('n-e', { name: 'x', filter: { nope: 1 } })
    console.log('E 多余属性 →', JSON.stringify(e.content))
  })()
}
```

```yaml

- name: '@deepseek-ai/dsh-tools'
- name: './nested-schema.ts'
```


**输出**

```
生成的 JSON Schema（紧凑）:
{"type":"object","properties":{"name":{"type":"string","description":"Who"},"filter":{"type":"object","description":"Nested filter","additionalProperties":false,"properties":{"tags":{"type":"array","description":"Tag list","items":{"type":"string"}},"mode":{"oneOf":[{"type":"string","const":"fast"},{"type":"string","const":"slow"}],"description":"Exactly one"},"style":{"oneOf":[{"type":"string"},{"type":"string","enum":["a","b"]}]}}}},"required":["name"]}

   [body] 收到 args: {"name":"ada","filter":{"tags":["x"],"mode":"fast"}}
A 合法嵌套 → [{"type":"text","text":"ok"}]

   [body] 收到 args: {"name":"","filter":{"mode":"slow"}}
B 空字符串 → isError: false （schema 放行了！）

C oneOf 零命中 → [{"type":"text","text":"Error: invalid arguments: \"filter.mode\" must match exactly one oneOf branch (matched 0)"}]

D oneOf 双命中 → [{"type":"text","text":"Error: invalid arguments: \"filter.style\" must match exactly one oneOf branch (matched 2)"}]

E 多余属性 → [{"type":"text","text":"Error: invalid arguments: \"filter.nope\" is not a declared property (additionalProperties: false)"}]
```

退出码 `0`。

**四个观察**：

1. **嵌套结构完整转换**：object（带 `additionalProperties`）、array（带 `items`）、oneOf 原样进入 JSON Schema；违规消息带**完整路径**（`"filter.mode"`、`"filter.nope"`）—— 模型能精确定位改哪个字段；
2. **`oneOf` 是「恰好一个」不是「至少一个」**：D 用例两个分支都命中，**照样被拒**（`matched 2`，`json-schema.ts:522-523`）—— 比很多人熟悉的 anyOf 语义严格，目的是保证类型推导无歧义；
3. **显式对象节点必须声明开放性**：`additionalProperties: false` 让未声明属性直接违规（E）；隐式参数根对象保持开放（文档原话）。类型上 `ObjectValueSchemaSpec.additionalProperties` 是**必填**字段（`schema.ts:68-72`），想漏都漏不掉；
4. **B 是边界本身**：空字符串**通过了** schema —— DSL 没有 `minLength`。这就是文档那句「你仍需手动检查 schema DSL 无法表达的约束，例如非空字符串、正数或跨字段规则」的实测证明。**schema 挡住的是形状错误，挡不住语义错误** —— execute 里该写的检查一行都省不掉。

顺带：`oneOf` 节点旁不允许出现 `properties`/`enum`/`const` 等兄弟关键字（`ONE_OF_SIBLING_KEYWORDS`，`json-schema.ts:199-200、236`，注册时即拒）🚧 未实测；支持的关键字全集见 `json-schema.ts:267` 的报错文案：`type/oneOf/properties/required/additionalProperties/items/enum/const` + 注解（description/examples 等）。

## 8.5 UI 投影：纯函数与软校验

文档「工具在 UI 中的渲染方式」：`output.render` 管**模型可见**内容；UI 卡片是另一回事，由 `presentCall`（PENDING 卡片）/ `presentResult`（完成卡片）声明，返回 `card` 渲染意图（词汇表：`generic`/`terminal`/`diff`/`read`/`search`/`web`）。硬性规则第一条：**纯函数** —— 实时流式和会话日志**回放**都会跑它们，不许 I/O、不许时钟随机数。

为什么必须软校验？回放时的 args 可能来自**旧版 schema** 的日志。`defineTool` 的包装器（`schema.ts:594-609`）：args 校验不过 → 返回 `undefined`（UI 回退到通用卡片），**绝不抛异常** —— 「展示绝不能导致回放崩溃」。和 `execute` 路径的硬校验（`ToolArgsError`，[7.4](07-进入-harness.md#74-校验发生在-execute-之前)）形成对照。

**📄 文件** `01-learn-basics/examples/cordis-tutorial/08-presentation-soft/presentation-soft.ts`

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'presentation-soft'
// 没有 inject —— presentCall/presentResult 是纯函数，直接调用即可

export function apply(_ctx: Context) {
  const tool = defineTool({
    name: 'greet',
    description: 'Greet the named person.',
    parameters: {
      name: { type: 'string', required: true, description: 'Who to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
    // UI 卡片投影：调用期（PENDING 卡片）
    presentCall: args => ({ card: 'generic', title: `Greet ${args.name}` }),
    // UI 卡片投影：完成期
    presentResult: args => ({ card: 'generic', title: `Greeted ${args.name}` }),
  })

  console.log('① 合法 args:', JSON.stringify(tool.presentCall?.({ name: 'Ada' })))
  // @ts-expect-error 故意的：模拟旧版日志里的非法参数
  console.log('② 类型非法(42):', tool.presentCall?.({ name: 42 }))
  // @ts-expect-error 故意的：模拟缺必填字段的旧日志
  console.log('③ 缺必填({}):', tool.presentCall?.({}))
  // @ts-expect-error 故意的：非法 args 走完成期投影
  console.log('④ presentResult 非法 args:', tool.presentResult?.({ name: 42 }, { content: [], isError: false }))
  console.log('   —— 全部【没有抛异常】，非法 args 一律返回 undefined（通用回退）')
}
```


## 8.7 自测

**Q1**：五个扩展点的执行顺序是什么？各能改变什么？

<details>
<summary>参考答案</summary>

实测顺序（08-policy-chain，编号即输出顺序）：

```
tools/pre-execute → guard → tools/execute（环绕）→ body → post-execute → tools/result
```

| 扩展点 | 能改什么 |
|---|---|
| `pre-execute` | **跑不跑**（allow/deny/ask） |
| `guard` | 只能**再拒一次**（单调，翻不了案） |
| `tools/execute` | 环绕 body：截止时间/重试/指标，可换 `exec.signal` |
| `post-execute` | **结果**：换 content、换 value（重新过校验）、block、附加上下文 |
| `tools/result` | **什么都改不了**（emit + 冻结 + 观察方异常只 warn），只能观察 |

</details>

**Q2**：pre-execute 返回 `allow`，guard 返回一个字符串 —— 结果是什么？反过来（pre-execute deny，guard 返回 undefined）呢？

<details>
<summary>参考答案</summary>

两种情况**都是拒绝**，body 都不会运行（08-deny-guard 实测了第一种）：

- allow + guard 字符串 → `guardReason` 命中（`index.ts:1476-1478`：决策为 allow 时才查 guard），物化成 `Error: <guard 理由>`，`isError: true`；
- deny + guard undefined → deny 在 waterfall 层就已成立，guard 根本不参与「放行」—— 这就是「单调」：guard 只能加拒绝，不能撤销别人的拒绝。

区别只在理由来源：前者 content 是 `Error: <guard 返回的字符串>`，后者是 `Error: <name> <deny reason>`。

</details>

**Q3**：post-execute 替换了 content —— 模型看到什么？程序化代码拿到什么？想连规范值一起换该怎么做？

<details>
<summary>参考答案</summary>

08-post-execute 实测：

- 模型（和 `tools/result` 观察者、持久化事件）看到**替换后的 content**；
- 程序化代码从 `result.value` 仍拿到**原始规范值**（`"Hello, Replace!"`）—— value 是执行本地的，content 替换不动它；
- 想换规范值：`{ kind: 'accept', value: <新值> }` —— 新值会**重新过 output.schema 校验并重新 render**（`index.ts:1758-1770`）。`content` 和 `value` 不能同时给；失败结果（isError）不允许换 value。🚧 这两个分支我只读了源码，没实测。

</details>

**Q4**：execute 返回违反 output.schema 的值会怎样？和 body 直接抛异常有什么区别？

<details>
<summary>参考答案</summary>

都得到 `isError: true`，但错误来源和 code 不同（08-output-invalid 实测）：

- 违反 output.schema → `INVALID_TOOL_OUTPUT`，消息形如 `tool "bad-output" returned invalid output: "value" must be a string` —— 注册表在 render 之前校验成功值（`createSuccessResult`）；
- body 抛异常 → content 是 `Error: <异常消息>` —— 基础设施故障的表达方式。

设计约定：基础设施坏了**抛异常**；领域性的坏消息（如非零退出码）**写进规范值**让 render 解释。

</details>

**Q5**：为什么 `oneOf` 命中两个分支也被拒？schema DSL 表达不了哪些约束？

<details>
<summary>参考答案</summary>

`oneOf` 是**恰好一个**语义：命中 0 个或 2 个都违规（`(matched 0)` / `(matched 2)`，08-nested-schema 的 C/D 用例）。目的是保证类型推导无歧义 —— 两个分支都命中时，编译期无法确定该用哪个分支的类型。

DSL 表达不了的（实测 + 文档）：非空字符串（无 `minLength`，B 用例空串放行）、正数、跨字段规则 —— 这些要在 execute 里手动检查。schema 挡形状错误，不挡语义错误。

</details>

**Q6**：为什么 `presentCall`/`presentResult` 是软校验（非法 args → undefined），而 `execute` 是硬校验（非法 args → ToolArgsError）？

<details>
<summary>参考答案</summary>

调用时机不同：

- `execute` 的 args 来自**当下这次**模型调用，刚被流水线校验过，非法就该大声失败（模型需要错误反馈来自我纠正）；
- 投影函数会在**会话日志回放**时用旧日志里的 args 重跑 —— 那些 args 可能来自旧版 schema，按今天的 schema 校验不过是正常现象。回放不能崩，所以非法 args 一律返回 `undefined`，UI 回退到通用卡片（`schema.ts:594-609`，08-presentation-soft 实测四种非法输入全部静默返回 undefined）。

这也是「投影必须是纯函数」这条硬性规则的原因：回放环境里没有你依赖的副作用可用。

</details>

## 本章一句话总结

> 工具本体只管业务：**策略挂在五层钩子上**（pre-execute 决定跑不跑、guard 单调拒绝、execute 环绕运维、post-execute 改写结果、tools/result 纯观察），**契约由注册表强制执行**（输入 args、输出 value 都过 schema，违规就是 isError），**DSL 管形状、execute 管语义**（空字符串能过 schema），**投影软校验保回放不崩**。测不了的（jobs/PTC/UI/agent）都在 8.6 的地图里，别把源码推断当实测结论。
